## 🔥 一、认证授权（Step 8）

### 亮点 1：JWT + Redis 双 Token 自研方案

**项目场景**：用户登录认证，需要兼顾性能、安全、可控性。

**为什么不用 Sa-Token？**
- Sa-Token 黑盒、token 是 UUID 每次都查 Redis、扩展性差
- 大厂主流是自研 JWT + Redis，可控性最强

**技术方案**：
```
登录：
  1. 校验用户名 + 密码（BCrypt 验证）
  2. 生成 accessToken（2h）+ refreshToken（7d），都是 JWT 格式
  3. Redis 存白名单：access:{userId} → token / refresh:{userId} → token
  4. 返回双 token + 用户信息

请求验证（拦截器）：
  1. 取 Authorization 请求头
  2. JWT 验签 + 解析 → 拿到 userId（无需查 Redis）
  3. 查 Redis access:{userId} 是否匹配（防 token 被盗用 + 支持踢人）
  4. 失败抛 NotLoginException → @RestControllerAdvice 返回 401

无感刷新：
  1. accessToken 过期
  2. 前端用 refreshToken 调 /api/user/refresh
  3. 验证 refreshToken → 生成新 accessToken（refreshToken 不变）
```

**核心代码亮点**：
- `JwtUtil` 工具类：使用 `jjwt 0.12.x` 新 API（`Jwts.parser().verifyWith(KEY).build()`）
- `JwtInterceptor` 拦截器：实现 `HandlerInterceptor`，统一鉴权
- 白名单设计：注册/登录/刷新放行，其余 `/api/**` 必须登录
- BCrypt 密码加密：使用 Spring Security Crypto，自带盐值，防彩虹表

**性能优化点**：
- JWT 自包含 → 拿 userId 不查 Redis
- Redis 只查白名单（一次 GET）
- 比 Sa-Token 减少了一次 Redis 查询（Sa-Token 用 token→userId 映射）

**关联面试题**：
- ✅ JWT 和 Session 的区别？
- ✅ 为什么需要双 Token？
- ✅ refreshToken 怎么防盗用？
- ✅ 如何主动让 token 失效（踢人下线）？

**面试故事模板**：
> "我们用 JWT + Redis 双 Token 实现认证。JWT 负责无状态签名验证，Redis 负责白名单管理。
> 这样既能利用 JWT 的自包含特性减少 Redis 查询，又能通过删 Redis 主动让 token 失效，
> 实现踢人下线、改密码强制重新登录等能力。比 Sa-Token 更可控，比纯 JWT 更安全。"

### 亮点 2：Spring MVC 拦截器统一鉴权

**项目场景**：所有 `/api/**` 接口都需要校验登录，但不能写在每个 Controller 里。

**为什么用拦截器而不用过滤器？**
| 维度 | 过滤器 Filter | 拦截器 Interceptor |
|------|--------------|-------------------|
| 来源 | Servlet 规范 | Spring MVC |
| 能否注入 Bean | ❌ 不方便 | ✅ 直接 `@RequiredArgsConstructor` 注入 |
| 抛异常能否被 GlobalExceptionHandler 接住 | ❌ 接不住 | ✅ 在 Spring 容器内可以 |
| 范围 | 所有请求（含静态资源） | 只拦 Controller 路径 |

**核心代码**：
```java
// 1. 实现 HandlerInterceptor，重写 preHandle
public class JwtInterceptor implements HandlerInterceptor {
    public boolean preHandle(HttpServletRequest request, ...) {
        // JWT 解析 + Redis 校验
    }
}

// 2. 通过 WebMvcConfigurer 注册
@Configuration
public class WebMvcConfigure implements WebMvcConfigurer {
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new JwtInterceptor(stringRedisTemplate))
                .addPathPatterns("/**");
    }
}
```

- ✅ 拦截器和过滤器有什么区别？（[Spring面试题.md#L19](file:///Users/a1234/Desktop/学习总规划/2-Java相关内容/spring框架/Spring面试题.md#L19)）
- ✅ Spring MVC 拦截器三钩子？（preHandle / postHandle / afterCompletion）

## 🛡️ 二、统一异常处理（Step 3）

### 亮点 3：全局异常处理 + 统一响应封装

**项目场景**：传统写法每个 Controller 都要 try-catch，代码冗余且不统一。

**技术方案**：
```java
@RestControllerAdvice  // = @ControllerAdvice + @ResponseBody
public class GlobalExceptionHandler {
    
    @ExceptionHandler(BusinessException.class)
    public BaseResponse<?> handleBusinessException(BusinessException e) {
        log.warn("业务异常: code={}, msg={}", e.getCode(), e.getMessage());
        return ResultUtils.error(e.getCode(), e.getMessage());
    }
    
    @ExceptionHandler(MethodArgumentNotValidException.class)
    public BaseResponse<?> handleValidationException(...) {
        // @Valid 校验失败，取第一个错误返回
    }
    
    @ExceptionHandler(Exception.class)
    public BaseResponse<?> handleException(Exception e) {
        log.error("系统异常", e);
        return ResultUtils.error(ErrorCode.SYSTEM_ERROR);
    }
}
```

**核心设计**：
- `BaseResponse<T>` 泛型响应：`code` + `message` + `data`
- `ErrorCode` 枚举：业务码（40000=参数错、40100=未登录、50000=系统错）
- `ThrowUtils.throwIf(condition, errorCode)`：优雅断言，避免 if-else
- `BusinessException` 自定义异常：携带 ErrorCode 信息

**关联面试题**：
- ✅ Spring MVC 中如何处理异常？
- ✅ @ControllerAdvice 和 @RestControllerAdvice 区别？
- ✅ 拦截器抛的异常能被 @ExceptionHandler 接住吗？（能，因为在同一个 Spring 容器）

**面试故事模板**：
> "我用 @RestControllerAdvice 统一处理异常，把 BusinessException、参数校验异常、系统异常分类处理。
> 业务异常打 warn 日志、系统异常打 error 带堆栈。Controller 不再写 try-catch，
> 配合自定义的 ThrowUtils.throwIf() 工具，业务代码变成断言式风格，可读性大幅提升。"

## 🗄️ 三、数据访问（Step 6 + Step 7）

### 亮点 4：MyBatis-Plus 自动填充 + 逻辑删除

**项目场景**：`createTime`、`updateTime`、`isDeleted` 字段每次手动写，容易遗漏。

**技术方案**：
```java
// 实体类
@TableField(fill = FieldFill.INSERT)        // 插入时自动填
private LocalDateTime createTime;

@TableField(fill = FieldFill.INSERT_UPDATE) // 插入和更新时自动填
private LocalDateTime updateTime;

@TableLogic  // 逻辑删除
private Integer isDeleted;

// 实现 MetaObjectHandler
@Component
public class MyMetaObjectHandler implements MetaObjectHandler {
    public void insertFill(MetaObject metaObject) {
        this.strictInsertFill(metaObject, "createTime", LocalDateTime.class, LocalDateTime.now());
        this.strictInsertFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
    public void updateFill(MetaObject metaObject) {
        this.strictUpdateFill(metaObject, "updateTime", LocalDateTime.class, LocalDateTime.now());
    }
}
```

**双保险设计**：
- Java 层：MetaObjectHandler 自动填充
- 数据库层：`DEFAULT CURRENT_TIMESTAMP` 兜底

**逻辑删除的好处**：
- 数据可恢复（误删可救回）
- 关联数据保留（外键不会失效）
- MyBatis-Plus 自动在 SQL 加 `WHERE is_deleted = 0`，业务层无感知

**关联面试题**：
- ✅ MyBatis-Plus 如何实现逻辑删除？
- ✅ MyBatis 和 MyBatis-Plus 的区别？
- ✅ MyBatis-Plus 的 BaseMapper 提供了哪些方法？

### 亮点 5：Flyway 数据库版本控制

**项目场景**：多人协作时，数据库 schema 变更难管理，容易出现"线上跑了 v3，开发还在 v1"。

**技术方案**：
- 所有 DDL 写到 `src/main/resources/db/migration/V*__xxx.sql`
- Spring Boot 启动时自动检查 + 执行未应用的迁移
- Flyway 在 `flyway_schema_history` 表记录已执行的版本

**踩坑记录**（简历加分点）：
1. 缺少 `spring-boot-starter-jdbc` → Flyway 无法注入 DataSource
2. MySQL 用户权限不足 → `GRANT ALL PRIVILEGES ON *.* TO 'root'@'%'`
3. MySQL 8.0 必须加 `allowPublicKeyRetrieval=true`

**关联面试题**：
- ✅ 数据库版本管理你用过什么工具？
- ✅ Flyway 和 Liquibase 的区别？

## 🧪 四、参数校验（Step 4）

### 亮点 6：声明式校验 + 全局异常返回友好提示

**项目场景**：注册接口参数校验，传统写法在 Service 一堆 if-else。

**技术方案**：
```java
// DTO 上加注解
@Data
public class UserRegisterDTO {
    @NotBlank(message = "用户名不能为空")
    @Size(min = 4, max = 20, message = "用户名长度 4-20")
    private String username;
    
    @Pattern(regexp = "^1[3-9]\\d{9}$", message = "手机号格式错误")
    private String phone;
}

// Controller 加 @Valid
@PostMapping("/register")
public BaseResponse<UserVO> register(@Valid @RequestBody UserRegisterDTO dto) { ... }

// GlobalExceptionHandler 统一处理 MethodArgumentNotValidException
String message = e.getBindingResult().getFieldErrors()
    .stream().findFirst().map(FieldError::getDefaultMessage)
    .orElse("参数校验失败");
```

**核心点**：
- `@NotBlank` vs `@NotNull` vs `@NotEmpty` 的区别要会讲
- Java 正则要双反斜杠 `\\d`（字符串转义）
- Spring Boot 3.x 的 Lombok 必须配 `annotationProcessorPaths`

**关联面试题**：
- ✅ JSR-303 / JSR-380 注解你用过哪些？
- ✅ @Valid 和 @Validated 的区别？
- ✅ 怎么校验集合参数？（要在 Service 用 @Validated）
